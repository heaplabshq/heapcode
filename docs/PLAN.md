# Heap Code — Build Plan

Source of truth for **what we build, in what order, and when it's done**.
Spec details live in `docs/PRD.md`. Update checkboxes as work lands; never start a milestone before the previous one's exit criteria are met.

## Guardrails (how we stay on track)

1. **One milestone at a time.** New ideas go to the Backlog section, not into the current milestone.
2. **Exit criteria are the definition of done** — demoable behavior, not "code exists".
3. **`packages/core` never imports `vscode`.** Enforced by lint rule. This protects the JetBrains/Neovim future.
4. **Every feature works with a local model (Ollama)** before we call it done. Local-first is the product promise.
5. **No native-module dependencies without a JS fallback** (sqlite-vec, etc.). The extension must never fail to activate.
6. **Tests land with the milestone**, not "later". Mock provider fixtures for anything touching an LLM.
7. Scope changes → edit `docs/PRD.md` + this file first, then code.

## M7 — Safety & Verification Foundations ✅

Goal: ship the guardrails before increasing autonomy, not after — every later milestone increases how much untrusted content and unattended action the agent takes.

- [x] Untrusted-content trust-tagging: `ContextBlock` gains `trust?: 'trusted' | 'untrusted'`; every file/folder/selection/terminal/diagnostics/RAG-retrieved block from `contextCollector.ts` and `chatViewProvider.ts`'s attachments is tagged untrusted; `assembleContext` wraps them with a `[untrusted data]` header + `wrapUntrusted()` notice. `fetch_url`, all MCP tools, and all VS Code LM tools carry `untrustedOutput: true`; `execTool` in `loop.ts` wraps their successful results the same way before they reach the model (native `role:'tool'` and fallback `formatToolResult` both covered, since both read `result.content`)
- [x] `check_package_exists` tool (npm/PyPI registry check, fail-open on network errors) — for the model to call proactively
- [x] Automatic guard: `run_command` pattern-matches install-shaped commands (`npm/pnpm/yarn install|add`, `pip/pip3 install`, `poetry add`) and blocks them before spawning if any named package 404s on its registry — enforced by the system, not dependent on the model choosing to call check_package_exists first
- [x] `run_tests` tool (`verifies: true`) wrapping the same `runCommand()` machinery; `execTool` flips a `dirtySinceVerify` flag on any successful `write`-permission tool call and clears it on a successful `verifies` call; all 4 `finish()` call sites in `loop.ts` route through `shouldDeferFinish()`, capped at 2 nudges; gated behind new opt-in setting `heapcode.agent.requireTestsBeforeFinish` (default `false`)

**Exit criteria:** met. A session that reads a maliciously-crafted file/URL/MCP result gets it wrapped as inert data, not instructions; with `requireTestsBeforeFinish` on, `finish` can't fire while a write is unverified; installing a hallucinated package is blocked with a clear message regardless of setting. 9 new unit tests (`agent.test.ts`, `contextManager.test.ts`); full suite green (160 tests), typecheck + lint clean.

## M8 — Granular Checkpoints ✅

Goal: raise `ShadowGit`'s snapshot resolution from per-turn to per-tool-call, since self-repair retries, sub-agents, and background execution all need fine-grained rollback to run safely with less live supervision.

- [x] New `AgentOptions.beforeToolCall?(call, tool)` hook in core's `loop.ts` — fires for non-`read` tools only, right after a permission grant and before `execute()`
- [x] `AgentController` takes `shadowGit` as a new optional constructor dependency (mirroring `rag`/`mcp`/`repoMapIndexer`) and implements `beforeToolCall` by calling `ShadowGit.snapshot()`, keyed by tool-call id in a `toolCheckpoints` map
- [x] The resulting hash rides on `onToolResult` → `agentToolResult` → `ToolDisplay.checkpoint` (not `agentToolCall`, since the hash isn't known until after the permission gate — see decisions log) and persists on the tool's `StoredMessage` through history reloads
- [x] New `restoreToolCheckpoint` webview↔extension message + `ChatViewProvider.restoreToolCheckpoint()`, reusing the exact same `ShadowGit.restore(hash)` as the turn-level `restoreCheckpoint`
- [x] Webview: a "⤺ Rewind to before this step" button in each tool chip's expanded detail panel, next to the existing "Run in terminal" action
- [x] `SessionCheckpoint` (per-file revert-all) untouched — granular checkpoints are an additional timeline affordance layered on top, not a replacement

**Exit criteria:** met. In a turn with 5+ tool calls, each non-read call gets its own shadow-git commit and its own rewind button in the tool chip, independent of the turn-level "restore to before this message" and the session-level "revert all." 3 new unit tests in `agent.test.ts` covering the hook's read/write gating, ordering, and denial behavior; full suite green (163 tests), typecheck + lint clean.

## M9 — Modes Primitive + Plan/Act Gating ✅ (planModel/planProfile role deferred)

Goal: Plan-mode and Custom Modes (Architect/Debug/Reviewer) are the same mechanism — filtering which tools a session is even offered — so build the primitive once.

- [x] Generic persona primitive (`packages/vscode/src/agent/personas.ts`): `AgentPersona { id, label, description, allowedPermissions?, taskAddendum? }` + `filterToolsForPersona()`, threaded through `AgentController.start()` as a second filter alongside `disabledTools`. Named "persona" rather than "mode" to avoid colliding with the pre-existing chat-vs-agent `mode` toggle already in the webview
- [x] Built-in personas shipped alongside the primitive itself, not after: **Agent** (no restriction, default), **Architect** (read-only), **Debug** (read + execute, no writes/destructive), **Reviewer** (read-only) — a persona picker (mirroring the existing Ask/Agent dropdown) sits next to it in the composer
- [x] True Plan/Act gate: new `AgentOutcome`/`AgentRunStatus` value `'planned'`; `AgentOptions.planOnly` returns immediately after `events.onPlan?.()` fires instead of auto-continuing; a companion `resumePlan` option reconstructs the transcript as if the plan had just been approved and falls straight into the tool-calling loop — the two-call split (plan now, resume later as a *separate* `runAgent` invocation) needed no cross-call session state beyond the plan text + original task, both cheap for the host to hold onto. Gated behind new opt-in setting `heapcode.agent.planGate` (default `false`) layered on the existing `planFirst`; "Approve & Run" button appears in the agent-status banner for a `'planned'` result
- [ ] `planModel`/`planProfile` role — **deferred**, see decisions log

**Exit criteria:** met for the shipped scope. Nothing is written during a gated Plan phase until "Approve & Run" is clicked; switching persona measurably restricts which tools the model is even offered (verified: Architect/Reviewer keep only `read`-permission tools, Debug adds `execute` but not `write`/`destructive`). 10 new unit tests (`agent.test.ts` for the plan/resume split, new `packages/vscode/test/personas.test.ts` for persona filtering — the first test in that package, made possible because `personas.ts` has zero `vscode` import); full suite green (172 tests), typecheck + lint clean.

## M11 — Context Intelligence Upgrade ✅ (rerankHits integration + next-edit suggestions deferred)

Goal: give sub-agent orchestration (M12) a ranked repo map to inherit from day one instead of retrofitting it later.

- [x] Import/dependency-graph extraction (`core/src/rag/importGraph.ts`, reusing the existing tree-sitter AST): ESM `import`/re-export `export ... from`/CommonJS `require()`/dynamic `import()` for TS/TSX/JS/JSX; `import`/`from ... import` (including bare `from . import x` resolving to the actual sibling module, not just the package `__init__`) for Python. Resolves only against files already known to the index — unresolvable specifiers (npm packages, stdlib) are dropped, not part of the intra-repo graph. Persisted alongside `repo-map.json` (`RepoMapIndexer`'s `SerializedRepoMapV2`, migrating v1 data on load)
- [x] Ranking pass: degree-centrality (`core/src/rag/rank.ts`'s `rankByCentrality` — in-degree weighted 2x over out-degree), personalized with an additive boost for currently-open editor tabs and a recently-saved-files MRU list. Reorders `formatRepoMap`'s output via a new optional `rank` param (unranked/missing paths fall back to alphabetical, so nothing regresses when the graph has nothing to say about a file)
- [ ] `rerankHits` integration — deferred, see decisions log
- [ ] Stretch: heuristic next-edit suggestions — deferred, out of scope for this pass

**Exit criteria:** met. `repo_map` orders files by import-graph centrality personalized to what's open/recently edited, not alphabetically; a widely-imported file's importers rank ahead of unrelated ones; truncation under the char budget now drops least-connected files first. 20 new unit tests (`importGraph.test.ts`, `rank.test.ts`, 2 new cases in `symbols.test.ts`); full suite green (202 tests), typecheck + lint clean, esbuild bundle verified.

## M12 — Orchestration & Async ✅ (async execution scoped to surviving the sidebar closing, not quitting VS Code; per-substep sub-agent rewind UI deferred)

Goal: both items need Plan/Act's approve-then-run trust model (M9) and granular checkpoints (M8) to be safe with less supervision.

- [x] Sub-agent orchestration: new `delegate_task` tool (opt-in, `heapcode.agent.subAgents`, default `false` — same posture as `planGate`/`requireTestsBeforeFinish`) lets the agent hand off a self-contained piece of work to an isolated, fresh-context `runAgent()` call — mode-scoped (M9 persona, optionally named, but never more permissive than the parent's own persona — see `intersectPersonas` in the decisions log) and optionally on a different model profile. Shares the parent's `WorkspaceToolExecutor` (same workspace, same `SessionCheckpoint` — its edits count toward the same revert-all) and abort signal (Stop interrupts it too); every non-read tool call it makes still gets its own shadow-git snapshot via the same `beforeToolCall` hook (M8). Sequential by design (`await`ed inline as a normal tool call — see the earlier decisions-log entry on why not parallel). Sub-agents don't get `delegate_task` themselves — one level of nesting only. Reports back a summary (outcome + tool-call count/list + final narration) as the tool's result content
- [x] Background/async execution, scoped to "survives closing the chat panel/sidebar, not VS Code itself" (confirmed with the user, not assumed — see decisions log): turned out the agent loop already ran unaffected by the webview's visibility (it lives in the extension host, decoupled from the webview's lifecycle) — the two real gaps were (1) a freshly-reconnected webview (after being explicitly disposed, or a window reload) started blank with no idea a run was in progress or had just finished, and (2) nothing told the user a run had finished while they weren't looking. Both fixed: `ChatViewProvider`'s `ready` handshake now rehydrates the current conversation (reusing the same `{type:'conversation'}` mechanism `openConversation`/`editUserMessage` already used — deduplicated into `toDisplayMessages()`) plus a resent `agentStatus: running` if a task is still in flight; `postToWebview` fires a native VS Code notification (with a "Show" action) on any terminal `agentStatus` while the view isn't visible
- [ ] UI: individual per-substep tool chips + rewind buttons for sub-agent activity — deferred, see decisions log (the checkpoints themselves already exist via shadow-git; only the live per-step chat surfacing is missing)

**Exit criteria:** met for the scoped goal. A decomposed task visibly runs as a separate delegated sub-agent (its own model call, own persona/permission scope, own checkpoints taken) — "independent rewind" is possible in principle (the shadow-git commits exist per sub-agent step) but has no dedicated UI button yet, only the parent's own steps do. An agent task keeps running and now properly resumes/notifies across the sidebar being hidden, disposed, or the window being reloaded — "survives closing the editor" (quitting VS Code entirely) was explicitly descoped after checking with the user, not assumed. 4 new unit tests (`intersectPersonas` in `personas.test.ts`); full suite green (208 tests), typecheck + lint clean, esbuild bundle verified. Needs live F5 testing (not yet done): enable `heapcode.agent.subAgents` and confirm `delegate_task` produces a coherent summary; start a task, right-click-uncheck the Heap Code view (or Reload Window) mid-run, reopen it, and confirm it reconnects with the live transcript instead of a blank chat; confirm the completion notification fires when the view isn't visible.

Two gaps found during live testing, both fixed: (1) `heapcode.agent.subAgents` was only reachable via native VS Code settings, with nothing in the extension's own Settings screen pointing at it — a new "Agent" section in `SettingsView.tsx` now surfaces the toggle directly (wired through a new `settingsSetSubAgents` message), so the opt-in is discoverable without knowing the setting ID up front. (2) A Debug-persona agent (read+execute, no write) could still create/edit/delete files by running `run_command` with a shell command like `mkdir`/`rm`/`sed -i`/output redirection — `run_command`'s `execute` permission class doesn't distinguish "runs a command" from "runs a command that mutates the filesystem," so a write-restricted persona could reach write-equivalent effects the tool-list filter was supposed to block. Fixed with a heuristic (`looksFilesystemMutating` in `personas.ts`) that blocks such commands for any persona lacking `write`, checked in both the main agent's and sub-agent's execute paths. 12 new unit tests (`looksFilesystemMutating` cases in `personas.test.ts`, 17 total in that file); full suite green (217 tests), typecheck + build clean.

| 2026-07-04 | Image/vision input deferred to backlog | Requires content-part message types across provider, history, and webview; not worth blocking v0.1 |
| 2026-07-16 | Hybrid search (embeddings + BM25 via reciprocal rank fusion) on by default; contextual retrieval (LLM blurb per chunk before embedding) opt-in, off by default, new `contextModel` role | Hybrid search is free and purely algorithmic — same posture as `rag.rerank` defaulting on.
