# Changelog

## 0.5.0

- **Fixed: heapcode could not run on Windows at all.** Each project's state directory is named after its own path, so on Windows the drive letter's colon rode along into the name — and `:` is illegal in a Windows filename. Every attempt to save anything under `~/.heapcode/projects/` died with a bare `ENOENT` naming a path that looked perfectly ordinary. The first command of the first session hit it
- **A run gets 100 model turns instead of 25, and the limit is now a question rather than a wall.** A turn is one reply, so a batch of parallel tool calls costs one and a read-then-edit-then-test cycle costs three — real multi-file work spent the old budget long before finishing, and the run then ended on a summary of "what's done, what remains" that is indistinguishable from a completed job. In a session, reaching the limit asks whether to keep going and a yes continues **inside the same run**; only the final summary is ever saved to a conversation, so replying "continue" to a cut-off run had been restarting the model from a paragraph describing work it could no longer see. Headless, with nobody to ask, the run stops and says so on stderr next to its non-zero exit. Set the ceiling with `--max-iterations N` or `{ "maxIterations": N }` in `~/.heapcode/config.json`
- **`--verify "<command>"` — self-checking runs.** The command runs once the agent believes it's done; if it fails, the output comes back as a new turn and the agent fixes its own work, up to `--verify-max` runs (default 3). The exit code stays non-zero while the checks are red, whatever the agent concluded. The command is yours, not the model's: captured from your command line, spawned without a shell, never offered as a tool — so it's safe to hand to a run whose permission mode denies `run_command` outright
- **Every headless run now reports what it changed** — a `path | +n | -n` table in plain text, a `filesChanged` array in `--json`, and the full unified diff with `--diff`. Taken from the same shadow-git history that backs `/rewind`, so it includes files a `--verify` command reformatted
- **And what it read, and what it cost.** `filesRead` lists the files the run opened, in order; `usage` sums tokens over every model call the run made — agent turns, the compaction summary, sub-agents, verify cycles — and reports `null` rather than `0` when the endpoint doesn't say, because "not measured" and "free" are different answers to "did delegating this save anything?"
- **The browser UI (`heapcode web`) says how a run ended.** A run cut off at the step limit, interrupted, or one that never really acted used to end exactly like a finished one: the composer freed up and whatever the model last said stood as the answer

## 0.4.0

- **`heapcode web` actually serves the browser UI.** It shipped in 0.3.0 and returned a 404 the whole time: the published package was built without the UI bundle, and the build step that copies it in warns rather than fails when it's missing

## 0.3.0

- **Permission modes, with Shift+Tab to cycle them** — Plan (read-only, only read tools are even offered), Confirm (ask before every write, command, and destructive action), Auto-edit (edits apply silently, commands still ask), and Auto (edits and commands run freely). The current mode shows bottom-left and can be changed mid-run — the engine reads it per request, so escalating out of a wall of prompts doesn't mean restarting the task. `/mode <name>` jumps straight to one, and `--permission-mode` now sets the starting point for interactive sessions too, not just `-p`. Auto still asks before anything destructive: the toggle is one keystroke away, and an unrecoverable action taken by mistake is a different category of problem from an unwanted edit, which `/rewind` can undo. Modes reset to Confirm every session, so a permissive one is never silently inherited
- **Changed:** in Confirm mode, a saved "Always allow" grant from an earlier session no longer skips the prompt. A mode the UI calls Confirm has to confirm — a grant saved weeks ago quietly approving edits is indistinguishable from the permission system being broken. Grants still apply in Auto-edit and Auto, where less prompting was the point, and a grant made during the current session still stands. `/permissions` lists what's saved for a project and `/permissions reset` clears it — the command the engine's own messages had been pointing at without it existing
- **Fixed:** a model that writes its tool call as text instead of calling the tool no longer ends the run. Several open-weight models emit `<tool_call>`, `<function=…>` or Hermes-style JSON no matter what the endpoint supports, because they were trained on it; those replies read as narration, so the agent nudged until it gave up on a task it was actively trying to perform. Those dialects are now understood, and on an endpoint with real tool calling the model is asked once for a proper call before the text one is honoured
- **Fixed:** a model whose chat template has no tool support no longer fails the run. Many local GGUF builds reject any request carrying tool definitions, which surfaced as a 400 immediately after the planning stage — planning sends no tools, the turn after it sends all of them. That rejection now switches the run to the text-based tool protocol and carries on. `/nativetools off` makes the switch permanent for a profile and skips the retry
- **Web search — off by default.** `web_search` is offered to the model but refuses to run until you configure a provider with `/websearch`: DuckDuckGo (no key), Brave, Tavily, Serper, or a self-hosted SearXNG. Results are treated as untrusted content, the same as `fetch_url`. Requests are spaced per provider (Brave's free tier allows one per second) and 429s are retried with backoff
- **Better provider errors.** A 404 from a router that names its upstream now says the model isn't being served rather than telling you to check a base URL that demonstrably worked. A 400 that means "prompt longer than the context this server was started with" says so, and names both settings that fix it — local servers default to a small context regardless of what the model supports
- **Fewer lost turns.** A stalled stream ("Upstream idle timeout exceeded") is retried instead of ending the run, including when it carries no status code, and 408 and Cloudflare 52x are treated as retryable. A stream that stalled after emitting only reasoning tokens can now be retried at all — reasoning is display-only, so replaying it can't duplicate an answer, and refusing to retry threw away long thinks for nothing
- `/model` now filters as you type, and matches terms in any order — "nvidia ultra" finds `nvidia/nemotron-3-ultra-550b-a55b:free`, which a plain substring search never did
- **Fixed:** actions approved by a saved grant are now reported in the transcript. They used to happen with nothing on screen explaining why no prompt appeared
- **Fixed:** switching profiles mid-session left the tool-calling protocol on whatever the session launched with
- **Fixed:** HTML entities in fetched pages and search results (`Rust&#x27;s`) are now decoded

## 0.2.0

- **PR review** — `/pr-review` reviews the current branch's pull request and, only after you confirm, posts a real GitHub review with line-anchored inline comments and one-click suggestions. Large PRs are reviewed per file rather than truncated, so nothing goes unreviewed silently; anything that couldn't be reviewed is reported as unreviewed rather than passed over as clean. `/pr-review deep` adds an independent verification pass that re-reads the code and drops false positives before you see them. Uses your existing `gh auth login` session — no separate token to configure. The review engine is shared with the VS Code extension, so both give the same review
- **Security:** `fetch_url` can no longer reach private, loopback, or link-local addresses — including cloud metadata endpoints (`169.254.169.254`), which hand out IAM credentials. This matters because the agent reads web pages and MCP output, and text in those can steer it; redirects are now re-checked at every hop, so a public URL can't bounce into your internal network. Connections to your own model endpoint are unaffected — running Ollama or LM Studio on localhost or a LAN box works exactly as before
- **Fixed:** a command that hit the timeout, or that you stopped with Esc, was reported as killed while it kept running. Only the wrapper shell was being killed, so the real process survived — a dev server would hold its port, and because it also held the output pipe, the agent stayed blocked until that process exited on its own rather than for the length of the timeout. The whole process tree is now terminated
- Multi-line composer input — Option/Shift+Enter inserts a newline instead of submitting

## 0.1.0

- First release of the standalone `heapcode` CLI: agent mode with tools, permission prompts, and shadow-git checkpoints; semantic search (RAG) and repo map; MCP servers; personas, memory, Skills, prompt commands, and `@file`/`@folder`/`@workspace` mentions; opt-in sub-agent delegation; and a headless `-p` mode with `--json` output for CI
