Chrome extension · side panel

An AI browser agent that runs in your browser, not someone else's.

heapbrowse reads the page you are on and can operate it for you — search, filter, fill in a form, pull a list into a spreadsheet. It works in your own Chrome, in your own logged-in session, and it shows you every action before it takes one.

Get it on GitHub → Privacy

Not yet on the Chrome Web Store. Load it unpacked from the repository for now.

What it does

Ask about the page. Or ask it to work the page.

Read

Answers from what is actually there

It reads the page the way the browser itself does, through Chrome's accessibility tree — not by guessing at the markup. Specifications, delivery options, small print, the thing three screens down.

Act

Clicks, types and fills in forms

With real input events that pages cannot tell from yours. Nothing happens to a page until you have approved it, and anything that buys, pays, submits or deletes asks every time — whatever mode you are in.

Collect

Turns a list into a spreadsheet

Search results, product grids, job boards. It gathers rows across pages, de-duplicates them, and hands you CSV or JSON — the actual data, which never passed through the model on its way to you.

Hand back

Stops at the things only you can do

A login, a one-time code, a CAPTCHA, choosing a file. It says what is needed and waits. You do it on the page in front of you, and it carries on from there — no cloud browser to hand your credentials to.

Your data

There is no heapbrowse server.

The text of the pages you point it at goes to the model endpoint you configure, and nowhere else. Point it at Ollama on your own machine and nothing leaves it at all.

Page content Sent to your configured endpoint only, and only when a question needs it.
Your API key Stored on the device in chrome.storage.local. Never synced through your Chrome profile, never shown again after saving.
Your saved details Name, email, address and the rest stay on the device. The model is told which of them exist — never their values. Substitution happens locally, after you approve the action.
History and audit log On the device. Clearable from the panel at any time.
Analytics None. heapbrowse makes no network request to anywhere except the endpoint you configured.

The full statement is on the privacy page.

Permissions

What it asks for, and what each one buys.

A browser agent is only as trustworthy as its install prompt is honest. Here is the whole list, in plain terms.

Reading a site Granted one site at a time, when you point it at one — not the whole web at install. You will see an “Allow” button on any page it has not been granted.
Chrome's debugger How it reads the page as the browser does and clicks with genuine input events. Chrome shows a “being debugged” banner across the top of the window while a run is going. That is Chrome telling you the truth; it cannot be hidden, and it goes when the run ends. You can turn the debugger off in Settings and everything still works, more slowly and less reliably.
Tabs Reads the address of the tab you are on, so the panel can tell you which site is in scope and offer to allow it. Reading the page itself still needs the per-site grant.
Downloads Saves a file the page is offering, when you ask for the file rather than what is in it.

Models

Bring your own.

Ollama and LM Studio on your own machine, or OpenAI, OpenRouter, Groq, Together, Azure, vLLM — anything speaking the OpenAI-compatible API. Test the connection in Settings and the model field becomes a list of whatever that endpoint offers.

  • No account. No sign-up. No heapbrowse subscription.
  • Several endpoints side by side as profiles, each with its own key.
  • Switch model without leaving the conversation.
