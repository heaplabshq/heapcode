Privacy · last updated 29 August 2026

heapbrowse has no server, and collects nothing.

This is the whole policy, not a summary of one. heapbrowse is a Chrome extension that runs entirely on your device. There is no heapbrowse account, no heapbrowse backend, and no telemetry, analytics or crash reporting of any kind.

What leaves your device

One thing, to one place you choose: the text and structure of pages you point heapbrowse at is sent to the model endpoint you configure in Settings, so the model can answer questions about them. Nothing is sent anywhere else.

That endpoint is yours. If you configure Ollama or LM Studio on your own machine, nothing leaves the machine at all. If you configure a hosted provider, your data is handled under that provider's policy, and you should read it — heapbrowse is not a party to it and cannot see what they do with it.

Page content is only read when a question needs it, and only for sites you have granted access to, one site at a time. A screenshot is sent to the model only if the model explicitly requests one; screenshots taken to show you what it is doing are never sent anywhere.

What stays on your device

API keys Stored in chrome.storage.local, which does not sync through your Chrome profile. Written when you save and never read back into the form, so a stored key cannot be recovered from the interface or captured in a screenshot.
Your saved details Name, email, address, résumé text and the rest of the form-filling details. The model never receives their values. It is told which fields exist — “there is an email address on file” — and asks for one to be filled; the substitution happens locally, after you approve the action.
Conversations The current conversation is kept in session storage so the panel survives being closed and reopened. Cleared with the new-conversation button.
Task history and audit log What you have asked and what heapbrowse did about it, including every action and who approved it. Both are on the device and both can be cleared from the panel at any time.
Settings Endpoints, models, profiles and preferences. Local, not synced.

What heapbrowse never does

  • It makes no network request to any address except the model endpoint you configured.
  • It has no analytics, no telemetry, no crash reporting and no update pings of its own.
  • It never types into a password field, and never asks you to tell it a password or a one-time code so that it can type one. When a step needs a person, it stops and hands the page back to you.
  • It refuses to act on banks, brokerages and password managers, in every mode.
  • It does not sync anything through your Chrome profile.

Permissions

Site access is granted one site at a time, by you, and is revocable from Chrome's own extension settings at any time. heapbrowse requests no host permissions at install.

It holds Chrome's debugger permission, which is how it reads pages accurately and clicks with genuine input events. Chrome shows a “being debugged” banner whenever a run is attached; that banner cannot be suppressed and is not suppressed. The debugger can be switched off entirely in Settings.

Removing your data

Uninstalling the extension removes everything: Chrome deletes an extension's local and session storage with it. Individual pieces — history, the audit log, saved tasks, your details, a stored key — can be cleared from the panel before that, and site permissions revoked from chrome://extensions.

Changes and contact
